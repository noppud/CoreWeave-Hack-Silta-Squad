# Hackathon brief

Source: the user-provided `CoreWeave Hacks Participant Handbook.html`, read on September 12, 2026. [Original handbook](https://wandbai.notion.site/CoreWeave-Hacks-Participant-Handbook-3c9e2f5c7ef380eab21ecdde12620caf).

This is a working summary of the saved file, not confirmation of the current event details. The saved schedule says Saturday June 6 and Sunday June 7; verify the current dates, deadline, credits, and submission page onsite.

## Eligibility

- Teams may have up to five people; solo participation is allowed.
- The eligibility section requires an open GitHub repository. The submission section also mentions judge access instructions; a public repository satisfies the stricter wording. This team's GitHub repo was public when checked on September 12.
- Build the project during the hackathon. Disclose existing components; judging covers the new work. Work must primarily be the team's own.
- Use W&B. Weave tracing is a practical starting integration, but meaningful sponsor usage is also judged.
- Be present in person to build and demo, including some attendance on Saturday.
- AI coding tools are allowed.

## What judges look for

| Criterion | Evidence to prepare |
| --- | --- |
| Best Loop | A failed attempt, actionable feedback, a revised attempt, and measured improvement. |
| Creativity | A distinctive approach; meaningful agent collaboration if used. |
| Utility | One clear user problem and a useful result. |
| Technical execution | A working demo and understandable architecture. |
| Sponsor usage | Actual use of sponsor tools, with traces or other evidence. |

The handbook lists Best Use of Weave, Best Use of ARIA, and Best Use of marimo as track choices; all projects are eligible for Best Loop Design. It also mentions a Most Production-Ready award two weeks later. Confirm current tracks and awards.

## Submission and demo

- Submit on the AGI House platform. One teammate submits; list every member.
- Every teammate must sign in and complete the participant survey before submission can complete.
- Include a unique team name, project name, a 2–3 sentence summary, team roster, socials, repository URL, track, and sponsor tool/protocol descriptions.
- Explain what the agent does and how feedback improves its next attempt. Document frameworks, orchestration protocols, and RL environments actually used.
- Include the W&B project link. The handbook explicitly says the W&B project itself need not be public.
- Prepare a screen recording under two minutes. One section calls video optional, another lists it among required items; preparing one covers both.
- The live demo is strictly three minutes, with at most one or two slides and a short Q&A. Make the loop visible immediately.
- Ensure Zoom or [Zoom screen sharing](https://share.zoom.us) works.
